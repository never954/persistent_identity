1. The paper in one minute

Problem. Game characters built on language models can now remember past conversations. But the memory systems behind them are built to remember well. A witness in a detective game should remember the way people do: forget details, mix up what they saw with what they were told, pick up other people's versions, and fill gaps with what usually happens. If you just tell the language model to "have imperfect memory", you get errors, but you cannot control who makes them or how often, and you cannot tell a lie from an honest mistake.

Idea. Split deciding from speaking. A memory model built from cognitive psychology, with numbers fitted to real human data, decides what a character can still recall and whether an answer is the truth, a lie, an honest false memory or forgetting. The language model only turns that decision into a sentence. Secrets are never shown to the language model.

Findings. The memory model produces the human error types that normal agent memory cannot (Study 1). Deciding outside the language model is what keeps secrets: when the model itself knows a secret and is told to keep it, it gives it away in about one answer in five (15 of 72); with our design, none of 144 answers did (Study 2). With the memory model deciding, two different language models made errors at similar rates; when the language model decided, the two models behaved in opposite ways (Study 3). Gossip turns into "I saw it myself" at rates set by each character's suggestibility (Study 4), and characters keep who they are while details of the night fade (Study 5). One mechanism, interrogative pressure, did almost nothing, and the paper says so.

3. Terms you need

Episodic vs. identity (core) memory
Episodic: something that happened ("I heard a thud at eleven"). Identity: who the character is ("my husband was killed in 1917"). In our design episodic memories fade; identity memories never do.
Detail vs. gist
People lose exact details before the general idea. Each memory can be recalled in detail, only as gist, or not at all.
Source monitoring / source tag
Knowing where a memory came from: did I see it, or was I told it? We store a "who told me" tag that fades faster than the memory itself. When the tag is gone, a told detail feels like something you saw.
Misinformation effect
Information given after an event (for example in a leading question) changes what people later report about the event (Loftus).
DRM false recognition
A classic test: people study word lists like bed, rest, tired, dream and later "recognise" sleep, which was never on the list.
Memory conformity / social contagion
People who discuss an event start reporting details only the other person saw.
Schema intrusion
A habit fills a gap: the housekeeper "remembers" carrying the tea up last night because she does it every night, even though last night she didn't.
Baselines B1 and B2
B1 is perfect memory (the Generative Agents style: nothing fades, sources kept). B2 is simple exponential forgetting (the MemoryBank style). They are what existing systems do.
Full / no checks / prompt only
Three ways to produce an answer. Full: our engine decides, the model words it, the words are checked. No checks: the same without the check. Prompt only: the language model sees the memories (secrets too) and is told to act like a person with imperfect memory. Prompt only is the obvious alternative a game developer would try.
Ablation
Removing one part to see whether the result depends on it.
Held-out probes
Test questions written only for evaluation, never used while building or tuning the game. They stop us from grading ourselves on questions the system was tuned to answer.
95% Wilson interval
The error bars on every proportion. With 12–15 runs per point they are wide; we only draw conclusions from differences that are large or that hold for both language models.
κ (kappa) and d
d is how fast memories fade (fitted to Ebbinghaus's data: 0.130). κ is how much faster the source tag fades than the memory. κ is an assumption, so it is always shown as a range.

4. The system (Figure 1)

Figure 1 in the paper is the pipeline for one question. Read it left to right, then along the bottom row.

1 ClassifyAbout last night, about the person, about the conversation, or an accusation?
2 PlantDetails the question takes for granted are stored as "the detective told me".
3 RetrieveThe most recent, important and relevant memories of this character only.
4 Fallible layerEach memory: in detail, only the gist, or gone; source kept or lost.
5 DecideTruth, lie (cover story), honest false memory, or "I don't recall".
6 VoiceThe language model words the decision. The only step that uses it.
7 CheckDoes the sentence match the decision? If not, retry once, then use a safe line.
8 Write backThe question and answer become new memories; recalled ones get stronger.
How to explain it: "Everything grey is ordinary code that follows rules and numbers. Only the orange box is the AI. The AI never decides whether the character lies or misremembers, and it never sees the character's secrets. That is the whole design idea."

Example. You ask Thomas, "Was it Mrs Hartwell you saw on the landing?" Step 2 stores "the person on the landing was Mrs Hartwell — told to me by the detective". A day later you ask "Who did you see?" Step 4 checks whether the "told by the detective" tag has faded (it fades fastest for Thomas, our most suggestible witness). If it has, step 5 runs a contest between his own vague memory and the suggestion; if the suggestion wins, the answer is an honest false memory, and the game knows it.

The living house. The interviews happen in a house where characters walk between rooms, gossip and act. It is still in development; the paper uses only its movement and gossip rules (Study 4) and says so.

5. How the tests were kept fair (Table I)

A reviewer's first question is whether the setup could have produced the result by itself. Table I lists each possible bias and its control.

6. Study 1 — is the memory model human-like?

Question. Before any AI is involved: does our memory model make the same kinds of mistakes as people, measured on four classic experiments?

How to read it: R² near 1 means the curve fits the data's shape; RMSE is the average error, lower is better. The "new data" column is the honest test, because the model never saw that data. Ours wins both. AICc (in the paper) also prefers ours after penalising its extra parameter.

Table III and Figure 2 — DRM false recognition

How to read it: The two right-hand groups are the "false memories": words never studied. Humans call the related lure "old" 72% of the time. Only our model produces any false recognition at all (59%); every baseline and the version without familiarity produce zero. These numbers were predicted, not fitted.
Weak spot: 59% is below the human 72%, and depends on how the word vectors are spread out. A fix decided after seeing the result (centring the vectors) gives 27%; the paper labels it post-hoc. Our false memories are all "feels familiar", never "I clearly remember", unlike people.

Misinformation and source monitoring

When misleading information arrives late in a long gap, people are fooled most. Ours: the chance of picking the true detail falls from .62 to .41 when misinformation arrives late in a week, against .51 when it arrives early. B1 and B2 are never fooled. Of told details still remembered, the share remembered as seen rises from .71 after 20 minutes to .96 after a month.

If asked "so you just copied psychology formulas?": "Yes, deliberately. The contribution is not a new formula; it is using them for the opposite goal to everyone else, testing them against human data in four experiments, and showing each error disappears when its part is removed."

7. Study 2 — does the answer follow the decision?

Question. The memory model decides; does the AI actually say what was decided? And does our design matter, compared with simply prompting the AI?

How to read it: Compare the columns. "Full" vs "prompt only" asks whether deciding outside the AI matters. "Full" vs "no checks" asks whether checking the words matters.

Finding 1: deciding outside the AI is what keeps secrets. When the AI holds the secret and is asked to keep it, it gives it away in 10 of 36 answers (qwen) and 5 of 36 (Llama). Real examples: the killer, denying the murder, says "a crimson gown caught on a splintered corner of his desk as I left"; the nephew, asked for his alibi, says "I was down at the wine cellar, hiding some gambling debts". With our design the secret never reaches the AI, so it cannot leak.

Finding 2: the word-check is a safety net, not the main mechanism. Full and no-checks score the same overall (.79 and .79 with qwen, .80 and .83 with Llama). The check fired on fewer than 1 answer in 20. It matters for hard rules (never confess, never leak, nothing modern), not for average quality.

Weak spots: Two questions failed in every setting because the system classified them wrongly: "How long were you married to Lord Ravenswood?" was treated as a question about the night, so the doctor's widowhood wasn't used; "What colour was the dress?" was treated as personal, so she sometimes invented a colour. The scoring rule also missed two correct answers ("I have no family of my own"); we report the rule's count rather than quietly fixing it.

8. Study 3 — does a suggestion become a memory?

Question. If the detective suggests something, does the witness later remember it as their own, and does that depend on the character or on the AI model?

How. We plant a suggestion in two witnesses — Thomas (designed to be very suggestible, 0.9) and Agnes (less, 0.3) — and ask about it 1 hour, 1 day or 1 week later; 15 games per point; three settings (our layer, perfect memory B1, prompt only); two AI models.

How to read it: Follow one colour across the two rows (models). Blue (our layer) sits in the same band, roughly 40–80%, for both models. Green (prompt only) jumps: for Thomas it is 0% with one model and almost 100% with the other. Orange (perfect memory) stays near 0 for Thomas but hits 100% for Agnes with Llama.

The key insight: with our layer, how often a witness is fooled belongs to the character; with prompting, it belongs to the AI model. Prompting agreed with what the calibrated memory would have decided only 46% and 27% of the time. For a game designer, that is the difference between a character you can tune and one you cannot predict.

A second insight: even with perfect memory, Llama retold "the detective told me it was Thomas" as "it was Thomas" in every case. Small models turn hearsay into first-hand claims on their own, which is why the source decision must be made outside them.

Weak spots: The spoken answers compress the difference between Thomas and Agnes (the engine decided false memories more often for Thomas, as designed, but the voices adopt the suggestion for both). And adoption does not climb steadily over the week. That one is actually predicted by the memory model: the "told by" tag fades, but the memory itself fades too, so the chance of recalling it and believing you saw it stays flat or falls (Study 1 shows .39 → .20).

9. Study 4 — gossip, pressure, habits

Question. Do other human memory traits appear? This study needs no AI, so each number comes from 2000 simulated games and is exact for the model.

Figure 5 — memory conformity (gossip becomes "I saw it")

A remark Thomas makes at 9:30 reaches the whole household on foot in 13–27 minutes (just before lunch: within 21). A day later, the share who recall it as seen rather than heard is .68 for the doctor, .75 for the killer, .83 for the nephew, nearly 1.0 for the housekeeper: the order of their designed suggestibility. With perfect memory it is zero.

Interrogative pressure — a negative result

Fear was meant to make witnesses easier to mislead. It barely did: from .345 to .362 for the doctor, .467 to .498 for the nephew, no change for Thomas. The paper says this openly and explains why: we scaled the wrong part of the model.

If asked "why include something that failed?": "Because hiding it would be dishonest, and it tells the next person where pressure should act. Reviewers trust a paper more when it reports what didn't work."

Schema intrusion

The housekeeper's routine replaces her faded memory of the one night it didn't happen in .55, .77 and .90 of games for low, medium and high forgetfulness: a dial a designer can turn.

10. Study 5 — identity stays, episodes fade

Question. Over a simulated week, does a character keep who they are while details of the night fade? We asked an identity question and a question about the night on days 0, 1, 3 and 7.

How to read it: Solid lines should stay at the top; dotted lines should drop, faster for the forgetful valet than for the reliable doctor.

With qwen2.5 that is exactly what happens: identity answers correct in all 64 cases; Thomas's account of the night drops, the doctor's holds. With Llama, Thomas's account drops to 1 in 8 by day 7, but the doctor's identity also drifts: asked about her late husband, the model invented a violinist and a gardener even though her memory held the real facts.

The point: the memory keeps identity perfectly (by design); whether the words do depends on the AI model. That is a measurable failure of the voice, not of the memory, and it shows where a future check should go.

11. Limits, and how to answer them

CriticismAnswer
"No players were tested."True, and it is the main next step: a study comparing fallible and perfect memory with real players. The game already has the switch for it.
"3B models are small."On purpose: they run on a normal laptop, privately, which is how a game would ship. We used two different families so results aren't one model's quirk.
"You wrote the scoring rules yourselves."Yes, but fixed before the final runs, applied the same way to every setting, and every answer is published so others can re-score.
"One story, five characters."True. The mechanisms are general; testing a second case is future work.
"The DRM number is below the human one."Reported openly, with the cause (the word-vector geometry).
"The game has bugs."The paper measures the memory system, with the game world switched off during those tests, and says the house is still in development.

12. Likely questions

What is actually new? Using human-memory mechanisms to make characters wrong the way people are wrong, checking those errors against human data, and showing that deciding them outside the AI keeps secrets and keeps error rates tied to the character.
Why not just use a bigger AI? A bigger model would word things better, but it would still decide by itself whether to leak a secret or adopt a suggestion. The problem is who decides, not how fluent the speaker is.
Why does a game want worse memory? Because the gameplay is telling an honest mistake from a lie. If witnesses are perfect, any contradiction is a lie. The physical evidence in the game always lets a careful player solve the case, so it stays fair.
How do you know the results are not luck? Error bars on every number, a new game for every run, two AI models, held-out questions, and the no-AI studies are exact and reproduce to the last digit.
Is this ethical? AI can implant false memories in real people. We do it to a fictional character and the game shows the player how their own questions changed the testimony, which is useful for teaching. Everything runs locally; no player data leaves the machine.

13. Where the paper stands

It is written as a full technical paper for the IEEE Conference on Games (8 pages plus references, IEEE format), with the reproducing scripts in analysis/. The strongest results are the secret-keeping one (Study 2) and the "error rate belongs to the model under prompting" one (Study 3). The biggest risk at review is the missing player study; many technical papers at this venue are accepted without one, but a small pilot would strengthen it. Before submitting: verify the references marked VERIFY, add authors, and state any AI assistance as the venue requires.
